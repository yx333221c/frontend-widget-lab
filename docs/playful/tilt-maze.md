# 倾斜滚球迷宫（Tilt Maze）制作教学

> 目标：把指针相对盘心的偏移当平台倾角，让球带速度、带摩擦地滚动，撞墙沿法线弹开，并且一局一局真的能通关。
> 产出文件：[`widgets/playful/tilt-maze.html`](../../widgets/playful/tilt-maze.html)
> 难度：高级 · 约 50 分钟

---

## 0. 先想清楚：追指针 + 撞墙回退 为什么不对

最常见的写法（反例，不是本组件代码）：

```js
// 反例：追手指 + 撞墙回退
function move(e) {
  var dx = e.clientX - ballX, dy = e.clientY - ballY;
  ballX += dx * 0.1; ballY += dy * 0.1;          // 球追手指
  walls.forEach(function (w) {
    if (ballX > w.x && ballX < w.x + w.w && ballY > w.y && ballY < w.y + w.h) {
      ballX = lastX; ballY = lastY;               // 进墙了就回到上一个位置
    }
  });
}
```

三处露馅。球没有速度：手指停它立刻停。回退到 `lastX/lastY` 会让球贴在墙前发抖，因为下一帧又被拉回同一堵墙。位移写在 `mousemove` 里，一帧可能走 3 像素也可能走 60 像素，碰撞判定和事件频率绑死。要能玩，得补三样：每帧积分的速度向量、算得出"该被推到哪"的解算、跟刷新率无关的时间步。

## 1. 输入：指针偏移就是重力分量

盘心是原点，指针的归一化偏移直接当加速度：

```js
function setPoint(e) {
  var b = stage.getBoundingClientRect();
  var cx = b.left + b.width / 2, cy = b.top + b.height / 2;
  tilt.x = clamp((e.clientX - cx) / (b.width / 2), -1, 1);
  tilt.y = clamp((e.clientY - cy) / (b.height / 2), -1, 1);
  hasPoint = true; wake();
}
```

夹到 `±1` 是为了让"指针甩到盘外"和"指针贴到盘边"效果一致，`G = 1100` 才有确定含义。键盘、指针、真机倾角在 `readTilt()` 里汇成一个归一化倾角（键盘优先，真机倾角叠加而非替换），物理只写一遍：

```js
var f = Math.max(0, 1 - CFG.mu * dtS);
ball.vx += gx * dtS; ball.vy += gy * dtS;
ball.vx *= f; ball.vy *= f;
```

> 坑：症状是"高刷屏上球很快停住、低刷屏上一路滑行"。原因几乎总是摩擦写成 `ball.vx *= 0.98`。那是每帧系数，一秒衰减的次数等于屏幕一秒画的帧数，两种屏幕上滑的是不同的地面。改成 `v -= v*mu*dt`（等价于 `v *= (1 - mu*dt)`，`mu` 量纲是 1/秒）才与帧率无关。`Math.max(0, ...)` 是保命的：`dt` 一旦大于 `1/mu`，`1 - mu*dt` 变负，速度整个翻向。

`mu` 取 `2.4` 接近"玻璃球在桌面"，`0.5` 是冰面，`8` 松手即停、操作精度要求变高。

## 2. 为什么必须分轴解算

球和墙都是轴对齐矩形（球用外接方盒近似），重叠判定四行：

```js
function hits(w) {
  var r = CFG.r;
  return ball.x + r > w.x && ball.x - r < w.x + w.w &&
         ball.y + r > w.y && ball.y - r < w.y + w.h;
}
```

问题全在"怎么推开"。合成位移版本（反例）：

```js
// 反例：合成位移 + 最小穿透轴
ball.x += vx * dt; ball.y += vy * dt;
if (hits(w)) { /* 沿最小穿透轴推出 */ }
```

它的症状很具体：球斜着冲向墙角会穿出去。这一步同时带着 X、Y 两个穿透量，而"最小穿透轴"只看几何不看运动方向：几乎水平、略微向下的球，垂直只插进 2px、水平插进 14px，按最小穿透只把它往上抬 2px，下一帧插得更深，最后从墙的另一侧冒出来。分轴解算就是先只走 X、把 X 的重叠解决完，再只走 Y：

```js
for (var s = 0; s < n; s++) {
  ball.x += ball.vx * h; resolveX();
  ball.y += ball.vy * h; resolveY();
}
```

```js
function resolveX() {
  var r = CFG.r;
  gather(ball.x, ball.y, r);
  for (var i = 0; i < cand.length; i++) {
    var w = walls[cand[i]];
    if (!hits(w)) continue;
    if (ball.vx > 0) { ball.x = w.x - r; spark(w.x, ball.y); }
    else if (ball.vx < 0) { ball.x = w.x + w.w + r; spark(w.x + w.w, ball.y); }
    else ball.x = (ball.x < w.x + w.w / 2) ? w.x - r : w.x + w.w + r;
    ball.vx = -ball.vx * CFG.rest;              // 法线方向速度反向并衰减
  }
}
```

用 `vx` 的符号决定往哪推，推出方向就永远与运动方向相反，球不会被"吐"到墙的另一侧；`resolveY()` 完全对称。那个 `else` 不是装饰：`vx` 恰好为 0 且已重叠时前两个分支都不成立，球既不推出也不反弹，会永久嵌在墙里。

下表是把组件里的 `resolveX/resolveY/step` 原样抽出来跑的（`rest=0.3`，`dt=16.67ms`，`G=1100`，`mu=2.4`，`r=11`）：

| 用例 | 入位置 | 入速度 | 出位置 | 出速度 | 重叠 |
|---|---|---|---|---|---|
| X 正向撞 c8 墙 | (290, 133) | (300, 0) | (293, 133) | (-86.4, 0) | 无 |
| X 负向撞 c2 墙 | (126, 133) | (-300, 0) | (125, 133) | (86.4, 0) | 无 |
| Y 正向撞 row4 | (57, 140) | (0, 300) | (57, 141) | (0, -86.4) | 无 |
| Y 负向撞 row2 | (209, 126) | (0, -300) | (209, 125) | (0, 86.4) | 无 |
| 斜向进墙角 | (290, 140) | (300, 300) | (293, 145.1) | (-91.7, 305.6) | 无 |

第一行可手算核对：`vx` 乘摩擦得 288，位移 4.8，`290 + 4.8` 越过贴墙位 `304 - 11 = 293`，钳到 293，速度取 `-288 × 0.3`。斜向那行的 `vy = 305.6` 不是反弹值，只是摩擦加重力后的结果：X 解算钳到 293 时 `ball.x + r` 恰好等于墙左边缘 304，而 `hits()` 用严格大于，紧贴不算重叠，所以 Y 这步没做——球接着沿墙面下滑，撞上 row4 才被弹开，全程没有一帧嵌在墙里。一次只解决一个方向的穿透，代价是过直角会略微顿一下。顶墙静止时也不抖，抖动幅度只随 `rest` 变大：

| rest | 0 / 0.3 / 0.5 | 0.7 | 0.9 |
|---|---|---|---|
| 稳定段位置幅度 | 0.00px | 0.78px | 8.66px |

面板把 `rest` 上限放到 0.9，就是让你看到球在墙角发抖。

## 3. `dt` 归一与子步进

```js
var ms = last ? t - last : 16.7;
ms = Math.min(ms, 34); last = t;
step(ms / 1000);
```

为什么不固定 `dt = 1/60`？真实帧间隔在 8ms 到 33ms 之间浮动，固定步长得再套一层累加器攒时间。归一只损失一点严格性，换来参数含义清楚：`G` 就是"满偏时每秒加速 1100 像素"。`Math.min` 给后台标签页兜底：切回来时 `dt` 可能几百毫秒，不夹住球会一帧瞬移出迷宫。

夹住 `dt` 不等于位移小，子步数判据是"单步位移不超过半个半径"：

```js
var disp = Math.max(Math.abs(ball.vx), Math.abs(ball.vy)) * dtS;
var n = Math.min(8, Math.max(1, Math.ceil(disp / (CFG.r * 0.5))));
```

`Math.min(8, ...)` 是硬护栏，细分要花时间的，一帧最多解算 8 次；HUD 的"子步"字段实时显示 `n`，正常玩是 1 或 2。

穿不穿墙取决于单步位移与墙厚的比值。我按组件几何实测：让球以速度 `v` 撞向一堵单格墙，起始距离从贴墙扫到墙前 2 格，统计"落到墙另一侧"的用例数：

| 几何 / 速度 | 单步位移 | `n=1` 穿墙 | 判据给出的 `n` |
|---|---|---|---|
| 墙厚 38、`r=11`、`v=900`（默认） | 30.6px | 0/305 | 0/305 |
| 墙厚 38、`r=11`、`v=3000`（去掉 maxV） | 102px | 168/305 | 0/305 |
| 墙厚 16、`r=4`、`v=900` | 30.6px | 27/129 | 0/129 |

当前参数下 `maxV` 已经挡住最常见的穿墙路径，`n=1` 也没测出穿墙，子步进是第二道保险而不是必需品；但只要有人改小格子或放大速度上限，`n=1` 立刻开始穿墙（表里后两行）。判据按"位移 / 半个半径"算而不是按速度算，格子尺寸一变它就自动跟上。

## 4. 空间索引：每帧不该重扫所有墙

先把连续的 `#` 横向合并成长条矩形，墙矩形数量降到格子的三分之一。查询走网格桶：每格记着"可能压到它的墙下标"，一次只遍历球覆盖的那几格。去重靠自增的 `gen` 加一条 `stamp` 数组（`if (stamp[id] !== gen)`），而不是每次 `new Set()`：`gather` 每帧要跑 `2n` 次，在这种循环里分配对象是纯负担。`cand` 也复用，只清 `length`。这个量级全量扫描也够，加索引是给"格子更多、墙更密"留余地。

## 5. 迷宫生成：可通关是硬指标

第 1 关是手写字符图，`#` 是墙，`S` 起点，`G` 终点，通路可以直接手数出来：

```js
var LEVEL1 = [
  '###########',
  '#S...#....#',
  '#.#.##.##.#',
  '#.#.....#.#',
  '###.###.#.#',
  '#....#...G#',
  '###########'
];
```

随机迷宫在"奇偶格点"上做递归回溯：只在 `r`、`c` 都是奇数的位置开房间，打通时把中间那面墙一起挖掉，这样生成的房间天然连通。之后再随机挖掉若干"两侧都已是通路"的墙，把树形迷宫变成有环的：无环迷宫全是单通道，球斜着走会反复蹭墙。

到关判定用中心距离，比"球进格子"宽松，因为球半径 11 已经是格子 38 的四分之一：

```js
if (!won && Math.abs(ball.x - gcx) < CELL * 0.34 && Math.abs(ball.y - gcy) < CELL * 0.34) {
  won = true; winAt = performance.now();
  ball.vx *= 0.2; ball.vy *= 0.2;
}
```

`*= 0.2` 让球在格子里减速，像掉进洞中，延迟 900ms 换图，用户看得见"第 N 关"。

可玩性用组件里抽出的同一套函数验证：脚本化玩家按航点给满偏倾斜、到位松手，第 1 关 417 帧走到终点，0 帧重叠；随机 100 张图逐张先 BFS 确认连通、再用同一套物理驱动，全部通关且 0 穿墙；6000 帧随机方向长测也是 0 穿墙。浏览器里再用真实指针回读球心像素，右倾 1.2 秒右移 25.7px、左倾同样幅度回来，确认输入→物理→渲染这条链是通的。

## 6. `touch-action: none` 与 `deviceorientation`

```css
  .stage {
    position: relative; height: 244px; overflow: hidden;
    border-radius: 12px; touch-action: none;
```

`touch-action: none` 不是可选的。默认浏览器把触屏竖划当成滚动手势，一旦判定为滚动就停止派发 `pointermove`，症状是"手指一动球只走一小段然后停"。代价是该区域不能滚动页面，所以只给演示盘加。

`deviceorientation` 看着才是"真的倾斜设备"，但麻烦有三：iOS 13 起要用户手势调用 `DeviceOrientationEvent.requestPermission()`，否则 `event.gamma` 一直是 `null`；桌面和不少安卓浏览器直接派发 `null`，分不清"没权限"和"平放"；原始角度带着手持抖动，还要死区与低通滤波。所以组件里它只是可选通路，授权挂在 `pointerdown` 上：

```js
  function onOrient(e) {
    if (e.gamma === null && e.beta === null) return;        // 拿不到数据就当没有传感器
    if (BASE === null) { BASE = { g: e.gamma || 0, b: e.beta || 0 }; return; }
    CFG.level = {
      x: clamp((e.gamma - BASE.g) / 30, -1, 1),             // 左右倾 gamma：-90..90
      y: clamp((e.beta - BASE.b) / 30, -1, 1)               // 前后倾 beta：-180..180，要减基准角
    };
    wake();
  }
```

`BASE` 用第一批事件自己定：自然握持角不减掉，球会一直朝一个方向偏。30 度当满偏是经验值，小于它稍微一动就满速撞墙。这条通路在桌面空转，主输入必须是 `pointermove`。

空闲时循环照旧要停：连续 3 帧既没速度也没输入就断掉 `rAF`；「静止（停 rAF）」开关手动做同一件事并在盘上盖提示，`prefers-reduced-motion` 命中时默认进入该状态。

## 7. 接进真实项目

这套结构（输入归一 → 积分 → 子步进 → 分轴解算 → 空间索引）去掉迷宫部分是通用的 2D 刚体骨架，可以套在弹珠台、躲避球、或者"把球滚进确认区"这类交互上。

- 适合：小游戏、教学演示、需要"有重量"的指针交互。
- 不适合：要求路径确定的场景（物理本身不确定）；实体上千的场景（逐个解算扛不住，该换四叉树）。
- 参数起点：`G` 800~1200、`rest` 0.2~0.4、`mu` 2~3，墙厚至少是球直径的两倍。
- `dt` 上限、`maxV`、子步上限三处互相牵连，改任何一个都要重跑穿墙扫描。

## 8. 自查清单

- [ ] 加速度与摩擦以"秒"为量纲，改刷新率手感不变
- [ ] `1 - mu*dt` 外面套了 `Math.max(0, ...)`
- [ ] 碰撞按 X、Y 分轴解算，推出方向取该轴速度符号
- [ ] `vx === 0` 且重叠时有就近推出的兜底分支
- [ ] 单步位移判据是"不超过半个半径"，并有 `Math.min` 护栏
- [ ] 墙厚至少是球直径两倍，或有 `maxV` 上限
- [ ] 候选查询走网格桶，循环里没有 `new Set()`
- [ ] 随机迷宫用奇偶格点生成，实测通关且 0 穿墙帧
