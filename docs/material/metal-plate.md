# 拉丝金属铭牌（Metal Plate）制作教学

> 目标：只用渐变和混合模式做一块有拉丝纹与高光的铝板，刻字阴影跟同一个光源走。
> 产出文件：[`widgets/material/metal-plate.html`](../../widgets/material/metal-plate.html)
> 难度：进阶 · 约 30 分钟

---

## 0. 先想清楚：一张金属贴图为什么不算做过

```css
.plate { background: url(metal.jpg) center/cover; }
```

本站要求零图片，这段引了 `metal.jpg`，先就不合格。就算允许图片还有三个问题：图是固定方向的，光源一变就得换一张；放大或高 DPI 屏下纹理会糊；想让高光跟着角度走只能靠 `filter: hue-rotate()` 之类整体调色，改不了条纹朝向。

金属外观拆成三项：沿某方向重复的细条纹、与条纹同向的亮带（两者共用同一个 `--hi`，所以亮带被拖成一条）、随光源换向的刻字阴影。三样都能用渐变表达，光源角度退化成"渐变轴的角度"，一个数管全局。

---

## 1. 拉丝纹理：极小周期的重复渐变

```css
.plate {
  background-image:
    linear-gradient(var(--hi),
      rgba(255, 255, 255, 0) 6%,
      rgba(255, 255, 255, .5) 46%,
      rgba(255, 255, 255, .14) 62%,
      rgba(255, 255, 255, 0) 92%),
    repeating-linear-gradient(var(--hi),
      rgba(255, 255, 255, .10) 0 1px,
      rgba(0, 0, 0, .09) 1px var(--grain)),
    linear-gradient(168deg, var(--m1) 0%, var(--m2) 44%, var(--m3) 100%);
}
```

三层从上到下是高光带、拉丝条纹、金属本体。先看纹理：亮纹固定占 `1px`，暗纹占剩下的部分，周期就是 `--grain`（滑块 `0.5` 到 `6`、默认 `3`）。周期越大条纹越可数；压到 `1px` 以下就进入下一节的采样问题。亮暗两条透明度都压得很低（`.10` / `.09`），反差小、频次高才是拉丝的做法。

周期小于 `1px` 会有麻烦：条纹比物理像素还窄时，栅格化采样和渐变周期互相干涉，板面可能出现本不该有的明暗带（摩尔纹），斜向角度下还伴随锯齿。这条是按采样原理推的，本站没有逐设备截图验证；滑块下限给到 `0.5px` 就是让你在自机器上试出来。

规避有两条路。一条是把周期守在一个像素以上，用条纹数量而不是密度做细。另一条是把纹理搬到独立元素上再轻微模糊：

```css
body.soft .brush {
  display: block; position: absolute; inset: 0; z-index: 1;
  background: repeating-linear-gradient(var(--hi),
    rgba(255, 255, 255, .16) 0 1px,
    rgba(0, 0, 0, .13) 1px var(--grain));
  filter: blur(.3px);
  mix-blend-mode: soft-light;
}
```

`filter` 只作用于元素自身，纹理留在 `background-image` 里糊不掉，所以必须搬家。代价见下一节。

> 坑：症状是开了抗锯齿之后，把铭牌挪到不同颜色的页面上，板面色调跟着变。原因是这层要用 `filter` 就得独立成元素，独立成元素后只能靠 `mix-blend-mode` 混回来，而它的输入是"祖先画完的那张图"，页面背景也算在内；`background-blend-mode` 没有这个问题，因为输入只有自己那几层。修法：给 `.plate` 加 `isolation: isolate`，把混合范围收在铭牌内；组件里那句 `isolation` 就是为这个准备的。

---

## 2. `background-blend-mode` 与 `mix-blend-mode` 选哪个

两者都写"怎么混"，作用域不同。

`background-blend-mode` 混合的是**同一个元素的多层背景**：高光、纹理、本体自上往下逐层混合，输入全来自这个元素。它不读背后的东西，因此不需要新的层叠上下文，也不受祖先绘制影响。

`mix-blend-mode` 混合的是**这个元素与它背后已画好的内容**，输入包含"祖先画完之后"的画面，于是必然牵动周围：想收住范围就要 `isolation: isolate`，或者父级建层。

铭牌的三层背景走前者：

```css
background-blend-mode: overlay, soft-light, normal;
```

层序一一对应：高光 `overlay` 到纹理，纹理 `soft-light` 到本体，本体 `normal` 直接铺。`overlay` 按底色分支：底色过半时白源结果是满值，过半以下是 `2 × 底色`；混合结果再按 alpha 与底色插值一次，`.5` 等于"朝那个方向走一半"。代入两段：底色 `0.4` 抬到 `0.6`，`0.9` 只抬到 `0.95`，高光扫过中间调动静最大、最亮处几乎不动。

纹理层要纠正一个想当然的说法：`overlay` 换成 `soft-light` 不是变强，是变弱。把 `.10` 白纹与 `.09` 黑纹叠到不同底色上，按规范的分支公式跑一遍（`0.2` 到 `0.96` 这段明度，我自己算了一遍）：条纹明暗跨度在底色 `0.5` 处是 `overlay` 的 `0.095` 对 `soft-light` 的 `0.043`，`0.9` 处是 `0.019` 对 `0.013`。还有一点要诚实写出：两种模式都随底色变化，`overlay` 从最暗到最亮的跨度比约为 12 倍，`soft-light` 约 8 倍，所以换模式换来的是"更弱"，不是"更稳定"。真要调条纹强度，正路是改 alpha 或 `--grain`。必须换的只有一种情况：抗锯齿模式把纹理搬成独立元素后只能用 `mix-blend-mode`，`.plate` 那句 `isolation: isolate` 就从"可选"变成"必需"。

结论：能在自身背景里混完就别动背后内容，少一个隔离要求就少一类绘制差异。

## 3. 刻字的方向：四组 `text-shadow` 的推导

沟槽里迎光那侧的壁被自己挡住，暗面出现在光源方向；背光侧的壁被照亮，亮面在反方向：

```css
.engrave {
  color: var(--pent);
  text-shadow:
    var(--sx) var(--sy) 1px rgba(8, 12, 22, .68),
    calc(var(--sx) * -1) calc(var(--sy) * -1) 1px rgba(255, 255, 255, .8);
}
```

`--sx` / `--sy` 是光源方向的单位向量乘 1px：

```js
var a = state.angle * Math.PI / 180;
root.style.setProperty('--sx', (Math.cos(a) * 1).toFixed(2) + 'px');
root.style.setProperty('--sy', (Math.sin(a) * 1).toFixed(2) + 'px');
```

屏幕坐标 `y` 向下，`225` 度时 `cos` 与 `sin` 都是负数：暗面落在左上、亮面落在右下，与光源在左上的假设吻合。凸起就是两层顺序互换（`body.emboss` 分支），角度不用改。

最容易错的是方向。面板上"凹陷 / 凸起 / 无阴影"三个按钮能把这件事看穿：两层阴影互换后字从沟槽变成凸字，颜色、模糊、偏移量一个都没改。倒角、外投影、螺丝亮斑也都由 `--sx` / `--sy` 算出，方向不是逐层调的，是同一个变量喂出来的。

还有一个符号上的反直觉之处：凹与凸的偏移**反号**。凸体的暗投影落在背光一侧（[`neumorphic-keys`](../../widgets/material/neumorphic-keys.html) 里写的是 `-Math.cos`），沟槽的暗面落在迎光一侧，因为挡住光的是那面朝着光源的壁。本站两套实现，前者算 `-cos/-sin`、后者算 `cos/sin`，同一个 225 度得到两种偏移方向。

## 4. 螺丝孔：多层 `radial-gradient`

一个 15px 的圆要同时表达孔壁暗环、螺帽金属、以及随光源移动的亮斑：

```css
.screw {
  background:
    radial-gradient(circle at 50% 50%, rgba(20, 26, 38, .9) 0 24%,
      rgba(255, 255, 255, .8) 30% 38%, rgba(255, 255, 255, 0) 46%),
    radial-gradient(circle at var(--sxp) var(--syp), #e4eaf4 0 26%, #97a4ba 64%, #59647a 100%);
}
```

第一层是孔壁：深色从圆心铺到 `24%`，接一条亮环铺到 `38%`，`46%` 处归零，这一段就是"陷进去"的边界。第二层是螺帽，圆心写成 `var(--sxp) var(--syp)`，JS 按光源角度把它顶向迎光侧。槽口用一个 `::after` 的深色长条（`height: 2px`）加 `transform: rotate(var(--slot))` 解决，六颗螺丝各给一个不同的 `--slot`。我先前写过一版十字槽：两条 `linear-gradient` 配 `background-size` 的百分比在 15px 的圆里叠，交点处两层黑重合，中心比两条臂都深，而百分比换算到这个尺寸只有几个像素，稍有偏差就歪。换成一根可旋转的长条后，槽的形状、深度、角度都由同一条声明决定。

## 5. 金属 preset：三色决定材质

```js
var PRESETS = {
  alu:   { m1: '#f2f5fa', m2: '#c5cede', m3: '#93a0b4', pen: '#7e8ba3' },
  brass: { m1: '#f8e6bb', m2: '#d6ac53', m3: '#9a7226', pen: '#7d5a17' },
  steel: { m1: '#eaf0f7', m2: '#a9b6c9', m3: '#6d7b91', pen: '#55637a' },
  anod:  { m1: '#cfbcff', m2: '#8b64da', m3: '#49308a', pen: '#382564' }
};
```

`m1 → m2 → m3` 是本体渐变的三段明度，材质差别几乎全在跨度上：铝的三段最接近，过渡平缓；不锈钢压到 `#6d7b91`，同一句 `linear-gradient(168deg, ...)` 就产出更硬的转折；阳极氧化紫靠饱和度而不是明度跨度。`pen` 是刻字颜色，取比 `m3` 再暗一档的同色系：刻进金属的字不该是黑字，它只是那块金属的暗版。

## 6. 性能：多层混合的栅格化代价

`filter` 让那一层单独栅格化一次；`mix-blend-mode` 要和"背后已画好的内容"混合，浏览器得维持更大的绘制缓冲，祖先还要有隔离组。两者叠加时重绘代价随面积和背后重绘频率增长，具体帧数本站未测。守一条就够：这块板子 `288×150`，别放大成整页。另外三条：带 `filter` 的层只做小尺寸；别加 `will-change: filter`，那只是让这层常驻显存；需要持续变化时改 `background-image` 的角度（本例改 `--hi`），别动 `filter` 半径。光源滑块的写入合并到 `requestAnimationFrame` 的一次回调里，避免同一帧多次重算三层背景。

## 7. 接进真实项目

最小包三样：三层 `background-image` 加一句 `background-blend-mode`、一段刻字 `text-shadow`、`--sx` / `--sy` / `--hi` 三个由光源角度算出的变量。把角度做成 props 让多个组件共享同一个"全站光源"，前提是所有组件守同一套符号约定（凸体背光、凹槽迎光）。

适合：设置面板卡片、序列号与徽章、硬件拟物控件。不适合整页背景、滚动列表项、以及要打印或深浅双主题的容器（金属三色是硬编码的明度关系，主题一换就散）。

`prefers-reduced-motion` 在这块板上没有要关的东西：它没有动画。

## 8. 自查清单

- [ ] 拉丝周期默认不小于 1px，且验证过最小值下摩尔纹的样子
- [ ] 纹理和高光写在同一元素的背景层里，用 `background-blend-mode` 而不是给每层建元素
- [ ] 用 `mix-blend-mode` 的那一层被 `isolation: isolate` 收住
- [ ] 刻字暗面在光源一侧，与倒角、投影、螺丝亮斑同向
- [ ] 光源角度改动时高光轴、阴影偏移、亮斑位置由同一个变量算出
- [ ] 刻字色是金属本色的暗版，不是黑色
- [ ] 没有任何图片文件、外部字体或网络请求
- [ ] 小面积使用；没有把这套层叠挂到滚动容器上
