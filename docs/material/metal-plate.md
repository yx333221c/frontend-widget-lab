# 拉丝金属铭牌（Metal Plate）制作教学

> 目标：只用渐变和混合模式做一块能反光的铝板，刻字像真的凿进去。
> 产出文件：[`widgets/material/metal-plate.html`](../../widgets/material/metal-plate.html)
> 难度：进阶 · 约 30 分钟

---

## 0. 先想清楚：一张金属贴图为什么不算做过

```css
.plate { background: url(metal.jpg) center/cover; }
```

放进本站的前提先不合格：它要一个图片文件。就算允许图片，还有三个问题跟随其后：图是固定方向的，光源一变就得换一张；放大或高 DPI 屏下纹理会糊；想让高光跟着角度走只能靠 `filter: hue-rotate()` 之类整体调色，改不了条纹朝向。

金属的视觉信息其实很规整：一层沿某方向重复的细条纹、一条方向与条纹垂直的高光带、以及刻字处随光源换向的双向阴影。三样都能用渐变写出来，光源角度就退化成"渐变轴的角度"，一个数管全局。

---

## 1. 拉丝纹理：极小周期的重复渐变

```css
.plate {
  background-image:
    linear-gradient(var(--hi),
      rgba(255, 255, 255, 0) 6%,
      rgba(255, 255, 255, .5) 46%,
      rgba(255, 255, 255, .14) 62%,
      rgba(255, 255, 255, 0) 92%),
    repeating-linear-gradient(var(--hi),
      rgba(255, 255, 255, .10) 0 1px,
      rgba(0, 0, 0, .09) 1px var(--grain)),
    linear-gradient(168deg, var(--m1) 0%, var(--m2) 44%, var(--m3) 100%);
}
```

三层从上到下是高光带、拉丝条纹、金属本体。本文先只看纹理那一条。一条亮纹固定占 `1px`，暗纹占剩下的部分，整段周期就是 `--grain`。默认 3px 时明暗比大约 1:2，看起来像细密的机械拉丝；调到 1.5px 更像磨砂，纹理开始发灰；推到 6px 就成瓦楞，一眼假。亮暗两条透明度都很低（`.10` / `.09`），金属靠密集的微小反差，不是强烈的明暗对比。

周期小于 1px 会出事。条纹比物理像素还窄时，栅格化的采样和渐变周期发生干涉，出现大片本不该存在的明暗带，这就是摩尔纹；在斜向角度下还会伴随锯齿。演示把周期滑块下限设到 `0.5px`，就是让你把它调出来。

规避有两个方向。第一条是把周期拉回 1px 以上，用条纹的数量而不是密度来做细感。第二条是把纹理搬到独立元素上，然后轻微模糊：

```css
body.soft .brush {
  display: block; position: absolute; inset: 0; z-index: 1;
  background: repeating-linear-gradient(var(--hi),
    rgba(255, 255, 255, .16) 0 1px,
    rgba(0, 0, 0, .13) 1px var(--grain));
  filter: blur(.3px);
  mix-blend-mode: soft-light;
}
```

`filter` 只能作用于元素自身，纹理留在 `background-image` 列表里是糊不掉的，所以必须搬家。搬家的代价见下一节。

> 坑：症状是纹理层一糊，整块铭牌连同后面的页面都跟着发暗。原因是这层要 `filter` 就得独立成元素，独立成元素后只能用 `mix-blend-mode` 混回板面，而它的混合输入是"祖先画完的那张图"，范围比原本一层背景大得多。修法：给 `.plate` 加 `isolation: isolate`，把混合限制在铭牌内；组件里那句 `isolation` 就是为这个准备的。

---

## 2. `background-blend-mode` 与 `mix-blend-mode` 选哪个

两者都写"怎么混"，作用域完全不同。

`background-blend-mode` 混合的是**同一个元素的多层背景**，输入完全来自这个元素自己：高光层、纹理层、本体渐变，自上往下逐层混合。它不读取元素背后的任何东西，因此不需要新的层叠上下文，也不会被祖先的绘制影响。

`mix-blend-mode` 混合的是**这个元素与它背后已画好的内容**。输入包含了"祖先元素画完之后"的画面，于是它必然牵动周围：想收住混合范围就要 `isolation: isolate`，或者父级建层。

铭牌的三层背景走前者：

```css
background-blend-mode: overlay, soft-light, normal;
```

顺序与 `background-image` 的层序一一对应：高光 `overlay` 到下层纹理，纹理 `soft-light` 到本体，本体 `normal` 直接铺。`overlay` 会让亮带在亮金属上更亮、在暗金属上更弱，这正是反射在高对比表面上该有的表现。抗锯齿模式因为纹理必须独立成层，混合就退回 `mix-blend-mode`，同时 `.plate` 上那句 `isolation: isolate` 就从"可选"变成"必需"。

结论：能只在自身背景里混完，就别去动背后内容。少一个隔离要求，少一类跨浏览器的绘制差异。

## 3. 刻字的方向：四组 `text-shadow` 的推导

凹陷的沟槽里，迎光那一侧的壁是背光的、被自己挡住，所以暗面出现在光源方向；背光侧的壁被照亮，亮面出现在反方向。写出来是：

```css
.engrave {
  color: var(--pent);
  text-shadow:
    var(--sx) var(--sy) 1px rgba(8, 12, 22, .68),
    calc(var(--sx) * -1) calc(var(--sy) * -1) 1px rgba(255, 255, 255, .8);
}
```

`--sx` / `--sy` 是光源方向的单位向量乘 1px：

```js
var a = state.angle * Math.PI / 180;
root.style.setProperty('--sx', (Math.cos(a) * 1).toFixed(2) + 'px');
root.style.setProperty('--sy', (Math.sin(a) * 1).toFixed(2) + 'px');
```

屏幕坐标 `y` 向下，默认 `225` 度时 `cos` 与 `sin` 都是负数，暗面落在左上、亮面落在右下，和光源在左上这个假设完全吻合。凸起的写法就是把两层顺序互换（`body.emboss` 那个分支），同一个角度不用改任何东西。

这里最容易错的就是方向。演示的"凹陷 / 凸起 / 无阴影"三个按钮可以把这件事看穿：方向搞反时字会立刻从金属里"浮出来"变成贴纸，哪怕颜色、模糊、偏移量全都一样。同一块板上的倒角、投影和螺丝亮斑也都从这两个变量算，所以只要刻字方向对，其余层的朝向自然一致。

还有一个符号上的反直觉之处值得记住：凹与凸的偏移是**反号**的。凸体的暗投影落在背光一侧（[`neumorphic-keys`](../../widgets/material/neumorphic-keys.html) 里写的是 `-Math.cos`），而沟槽的暗面落在迎光一侧，因为挡住光的是那面对着自己、也对着光源的壁。本站的两套实现里，前者算 `-cos/-sin`、后者算 `cos/sin`，同一个 225 度得到两种偏移方向，这才是物理上正确的样子。

## 4. 螺丝孔：多层 `radial-gradient`

一个 15px 的圆要同时表达孔壁暗环、螺帽金属、以及随光源移动的亮斑：

```css
.screw {
  background:
    radial-gradient(circle at 50% 50%, rgba(20, 26, 38, .9) 0 24%,
      rgba(255, 255, 255, .8) 30% 38%, rgba(255, 255, 255, 0) 46%),
    radial-gradient(circle at var(--sxp) var(--syp), #e4eaf4 0 26%, #97a4ba 64%, #59647a 100%);
}
```

第一层是孔壁：一圈深色接着 8% 宽的亮环，把"陷进去"的边界画出来。第二层是螺帽，圆心写成 `var(--sxp) var(--syp)`，JS 按光源角度把它顶向迎光侧，亮斑跟着光转。槽口用一个 `::after` 的深色长条加 `transform: rotate(var(--slot))` 解决，每颗螺丝给一个不同的 `--slot`，看着像工人随手拧的。原先想用两层 `background-size` 拼十字槽，结果是亮暗两层叠加后槽形发虚，不如一字槽干净。

## 5. 金属 preset：三色决定材质

```js
var PRESETS = {
  alu:   { m1: '#f2f5fa', m2: '#c5cede', m3: '#93a0b4', pen: '#7e8ba3' },
  brass: { m1: '#f8e6bb', m2: '#d6ac53', m3: '#9a7226', pen: '#7d5a17' },
  steel: { m1: '#eaf0f7', m2: '#a9b6c9', m3: '#6d7b91', pen: '#55637a' },
  anod:  { m1: '#cfbcff', m2: '#8b64da', m3: '#49308a', pen: '#382564' }
};
```

`m1 → m2 → m3` 是本体渐变的三段明度。跨度小（铝）就柔和，跨度大（不锈钢）就硬朗，阳极氧化紫靠的是饱和度而不是明度跨度。`pen` 是刻字颜色，取比 `m3` 再暗一档的同色系：刻进金属的字不会变成黑字，它只是那块金属的暗版。

## 6. 性能：多层混合的栅格化代价

`filter` 会让那一层单独栅格化一次；`mix-blend-mode` 要求它和"背后已画好的内容"混合，浏览器就得维持一个更大的绘制缓冲，祖先还要有隔离组。两者叠在一个大面积元素上时，滚动期间的重绘成本会明显高于普通渐变背景。

三条能守的边界：把带 `filter` 的纹理层限制在铭牌这种小尺寸元素内；不要给它加 `will-change: filter`，那只是让这层常驻显存；需要持续变化时改 `background-image` 的角度值（本例就是改 `--hi`），别动 `filter` 半径。演示没有做拖拽跟随的实时高亮，光源滑块拖动时写入被合并到 `requestAnimationFrame` 的一次回调里，避免一帧内多次重算三层背景。

## 7. 接进真实项目

拆出来最小可用只要三样：三层 `background-image` 加一句 `background-blend-mode`、一段刻字 `text-shadow`、以及 `--sx` / `--sy` / `--hi` 三个由光源角度算出的变量。把角度做成 props，多个组件共享同一个"全站光源"，比每个组件自带方向要可信得多。

适合：设置面板卡片、序列号与徽章、硬件拟物控件、日志里的一块"设备铭牌"。不适合整页背景、滚动列表项、以及任何需要打印或深色浅色双主题的容器（金属三色是硬编码的明度关系，主题一换就散）。

`prefers-reduced-motion` 在这块板上没有要关的东西：它没有动画，滑块才改变外观。

## 8. 自查清单

- [ ] 拉丝周期默认不小于 1px，且验证过最小值下摩尔纹的样子
- [ ] 纹理和高光写在同一元素的背景层里，用 `background-blend-mode` 而不是给每层建元素
- [ ] 用 `mix-blend-mode` 的那一层被 `isolation: isolate` 收住
- [ ] 刻字暗面在光源一侧，与倒角、投影、螺丝亮斑同向
- [ ] 光源角度改动时高光轴、阴影偏移、亮斑位置由同一个变量算出
- [ ] 刻字色是金属本色的暗版，不是黑色
- [ ] 没有任何图片文件、外部字体或网络请求
- [ ] 小面积使用；没有把这套层叠挂到滚动容器上
